## Why rebase

The C port is a port of asupersync 0.6.0, the current reference. The old
baseline predates semantic changes the port must follow, for example the
budget priority semiring (Rust takes the max of priorities, `INFINITE` has
priority 0 and `ZERO` 255; upstream `a16f46c5a`, `8195e9a1c`, `d9f3bda42`;
fixed in C under K1, bd-9kll.3.1).

The capture method changes with the baseline. The old fixtures came from
`tools/fixture_capture`, which synthesized most expected outputs instead of
recording asupersync running. The new corpus comes from the twin-run oracle
(W1.4, `tools/twin_run`), which executes the real `LabRuntime`.
`docs/TWIN_RUN_FEASIBILITY.md` shows that this works at 5e60b1c4c.

## Procedure

1. Capture the new corpus into staging only:
   `tools/ci/capture_rust_fixtures.sh` writes `build/fixture_staging/<run_id>/`
   and never touches `fixtures/rust_reference/`.
2. Run the comparator (W1.6) on every staged scenario against the C runtime,
   and against the old fixture where one exists.
3. Classify every delta in the table below.
4. Owner sign-off: fill in `approved_by` and `approved_at`.
5. `make fixtures-promote RUN_ID=<run_id>` copies the staged corpus into
   `fixtures/rust_reference/` and makes the pending baseline active (the old
   one moves to `history`). It refuses to run without the sign-off in step 4.

Mixing generations is a hard failure: `make fixture-integrity` rejects a
committed fixture whose provenance names a baseline other than the active
one.
