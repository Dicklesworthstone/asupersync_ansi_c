# Recorded parser divergences (bd-9kll.16.2), one family per line:
#
#   <signature> [<request shape>] | <bead> | <note>
#
# `make parser-differential PARSER_DIFF_MODE=gate` (and the CI step, once it
# gates) fails on a family whose key is not listed here, and prints a listed
# one that no longer appears as stale, so an entry goes when its bead is
# fixed. A key is the signature of tools/ci/parser_differential.py (see its
# header: rust-panic, rust-crash, c-crash, rust-accepts/c-rejects:<c reason>,
# c-accepts/rust-rejects:<rust reason>, both-accept:<field>[:<detail>]) plus,
# in brackets, the request feature that stays after reduction when that
# splits one coarse reject reason into root causes (leading-empty-line,
# target=double-slash, target=absolute-empty-authority,
# target=authority-empty-port).
#
# First recorded from seed 1 / 2000 inputs (C defaults) and seed 7 / 20000
# inputs (--c-require-host 0), asupersync 5e60b1c4c against the C parser at
# 3846ec4. No both-accept:* family was found: on the ~4000 requests both
# parsers accept, method, target, version, headers, trailers, body and
# bytes used agree.
#
# A response key starts with `response@<METHOD> ` (the request method the
# response is decoded against: GET, HEAD, CONNECT), and the bracketed shape
# adds the status class (status=1xx, status=204, status=304) when a bodyless
# status splits a reason. Responses were first recorded from seed 3 / 6000
# inputs (the CI step) and seed 1 / 2000 inputs with 29 families, all in five
# root causes (bd-9kll.16.2.9 to .13); the owner decided .9, .10, .12 and .13
# are aligned to Rust (the semantic delta budget is 0 and Rust is the
# reference), and the C parser was changed to match (src/net/http.c). What is
# left of the response corpus is two families: .8 and .11, listed below.
# No both-accept:* family was ever found: on the ~5400 (response, method)
# pairs both parsers accept, status, reason, version, headers, trailers, body
# length and digest, and bytes used agree.
#
# A WebSocket frame key starts with `ws-frame@<role> ` (the receiver, client or
# server), and the bracketed shape reads the first two bytes of the minimized
# frame (rsv, opcode=reserved, control, fin=0, len=16bit, len=64bit). The two
# families found (bd-9kll.16.2.14, .15: the close code of an oversized control
# frame and of a close reason that is not UTF-8) were aligned to Rust in
# src/net/websocket.c, which also fails a frame on its first two bytes as
# asupersync's codec does; no entry is left, and no accept/reject split or
# both-accept:* family was ever found (about 2500 frame and role pairs agree
# on fin, rsv, opcode, mask, key, payload length and digest, bytes used).
#
# `raptorq` (a dual oracle: C, asupersync's encoder and decoder, the crates.io
# raptorq 2.0.1 crate) has no entry on purpose: the three agree on every
# repair symbol and on whether each set of encoding symbols decodes (500000
# cases over ten seeds), and the CI step gates, so a first difference fails.
